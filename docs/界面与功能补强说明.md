# 界面与功能补强说明

对应 2026-10-27 发布的 2.3.0，旧版用户需升级后使用。依据源码审查实施；其中 AI 模式按用户要求保留默认联网和深度思考。

## 文献库与任务

- 每页 50 篇，按后端全库排序；页码、筛选数量一致。空结果可清空筛选。知识库侧栏分段加载完整文件列表。
- 标题固定两行，首行自然换行、仅第二行末尾省略；行高匹配两行文字。初始自动利用剩余宽度；手动拖动后按实际宽度保存，不受窗口宽度限制，超出可横向滚动。五列均可调宽并完整显示，已移除密度、标题行数和列显隐设置。
- 文件按实际是否存在显示“未获取 / 文件丢失 / PDF 已有”。索引、精读、分类错误独立保存；已有索引或摘要不会被误当成文件仍在磁盘上的证明。
- PDF 和精读按批次统计；任务中心保留最近 30 个批次，显示本批成功、失败及错误，支持仅重试本批失败论文。删除中的下载会结束为已取消；选择的论文全部不存在时不会意外启动全库精读。
- 详情、缩略图、精读、标签等异步结果只更新发起操作的论文界面，切到另一篇后不会跳回。

## 阅读器

- 按论文保存页码、页内位置、缩放和标签页。普通重开恢复进度，引用指定页优先。
- 侧栏可拖动宽度或折叠，提供适合宽度、适合页面和原始大小。
- 全文搜索显示逐处命中、高亮、上一处/下一处和搜索进度；可取消，切篇自动废弃旧搜索。
- 批注笔记使用页内编辑器，支持保存、取消和继续修改。

## AI 反馈与证据

默认联网和深度思考保持。支持时显示供应商实际返回的分析内容与回答增量；不提供 reasoning 字段时，深入分析路线请求简短公开分析摘要。没有分析输出时显示真实处理阶段，不编造百分比或思考过程。

各入口支持停止、重试和清空撤销。停止即时让前端旧结果失效，并通过后端版本阻止保存旧回答。若供应商只支持阻塞请求，已发出的那次 HTTP 调用可能仍需等待超时/返回；后续模型调用会检查停止状态。

证据卡区分原文、摘要、AI 概述、附件和网页；只有回答中实际编号引用的材料列入“本轮实际引用”，其余折叠为“检索候选”。缺 PDF 时显示“查看摘要 / 补齐 PDF”。可在文献库勾选多篇进行明确范围的比较，复制回答或将回答追加到指定论文笔记。追加由数据库单条更新完成，多个窗口并行追加不会互相覆盖。

## 设置与恢复

设置分为模型、阅读、PDF 来源、存储和插件。分组保存及未保存提示明确；保存响应在途时的新编辑仍保留为未保存。测试连接依据真实请求记录最近成功/失败，修改模型配置后旧成功记录失效。当前 PDF 目录可以直接打开。

清空会话同时移除附件和未确认草稿，可撤销恢复；清空后有新消息或材料时禁止覆盖。回收站恢复指定的记录，不会误恢复同一会话的另一条记录。

论文删除进入本地回收站，可恢复元数据、批注、索引和对话；原始 PDF 保留在磁盘。当前回收记录不自动过期。回收站位于设置的“数据与存储”。

数据备份 ZIP 包含文献元数据、笔记、批注、索引、订阅条目、对话及恢复记录，不含 PDF 实体和配置中的连接密钥、邮箱授权码。对话/笔记中用户自行写入的文本仍属于备份内容。PDF 目录需另外备份。

恢复会替换当前元数据，保留现有连接密钥；自动生成一份恢复前备份到本地数据目录的 `backups` 子目录。上传库先导入规范临时库、验证表列与引用并重建全文索引，不执行上传库触发器；正式导入使用单个事务，失败回滚。生成、下载、精读、分类或订阅同步仍在运行时先等待任务结束。旧队列记录恢复为已中断，不自动重启下载。恢复成功自动重载页面，避免聊天缓存持有旧版本。

对话框支持焦点限制、Esc 和退出焦点恢复；表单、标签页及来源控件补充可访问名称、状态和键盘操作。

## 验证范围

使用独立临时数据、合成文献与 mock LLM；未启动已安装程序，未修改真实文献库。关键脚本：

- `tests/test_workspace_hardening.py`：分页/状态、批次、撤销、回收站、备份合法性、事务回滚、在途停止与恢复互斥、并行笔记追加、连接状态。
- `tests/test_ai_conversations.py`、`tests/test_ai_feedback.py`、`tests/test_pdf_acquisition.py`：既有上下文、PDF 获取及真实协议形状的模拟流式回归。
- `tests/reader_ui.mjs`：阅读记忆、引用跳页、布局、逐命中搜索、异步隔离、笔记、批注、分析/回答增量与撤销。
- `tests/workspace_ui.mjs`：233 篇完整翻页、全库排序、详情竞态、分组保存期间继续编辑、任务重试、回收站、恢复后继续聊天、弹窗焦点。
- `tests/ai_feedback_ui.mjs`、`tests/ai_conversations_ui.mjs`：分析反馈、停止/重试、来源、比较、会话和附件隔离。

浏览器使用 headless Edge，截图见 `ui-review-2026-10-27/implementation/`。该验证不代表已连接每个真实 LLM 供应商、已认证出版社站点，也不等于完成屏幕阅读器人工审计。

本轮最终结果：Python 71 项通过，Node 测试入口 8 项通过；四份 Edge 交互脚本通过（阅读器 11 组、原会话 8 组，另含 AI 反馈及工作区完整流程）。冒烟脚本报告 20/20，其中“LLM 未配置错误路径”为脚本原有跳过项；其余检查已执行。最后一次工作区验证包含恢复备份后继续聊天及设置保存期间的新编辑。
