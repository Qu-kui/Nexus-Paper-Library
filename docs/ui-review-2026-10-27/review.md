# PaperWhale 界面与功能补强审查

2026-10-27。审查当前源码，不代表已安装程序已升级。使用独立临时数据目录、233 条合成文献及 headless Edge；实际查看 1500×1000 与 1100×720 的页面，未修改真实文献库或生产界面代码。原始测量见 `observations.json`，截图见本目录。

## 优先处理：信息与操作可信度

### 1. P1 — 超过 200 篇后列表不完整，排序也不是全库排序

- 实测：接口总数 233，界面只显示 200；标题仍写“共 233 篇论文”，没有翻页或加载更多。
- 代码：`web/js/library.js:7`、`:699` 请求固定 limit=200，不发 offset；`:675` 在这 200 篇上排序。`paperwhale_server/routers/papers.py:52` 永远先按更新时间取页。
- 影响：较早论文没有浏览入口，“按年份”“按标题”无法保证全库顺序。
- 建议：排序参数下沉到后端，明确分页/加载更多，显示“已显示 200 / 233”；大列表再做可见区域渲染。
- 验收：233 篇全部可浏览，切换排序时第一条确实是全库最早/最新年份或首个标题，筛选后数量与分页一致。

### 2. P1 — 文件存在性和处理状态显示不准确

- 实测：构造一个指向已不存在 PDF 的条目，接口仍返回 `has_pdf=true,status=indexed`。
- 代码：`paperwhale_server/db.py:239` 只判断 file_path 字符串；缺 PDF 筛选和统计也只检查空路径。
- 另外：`paperwhale_server/services/category_assistant.py:142` 仍把分类错误写入 pdf_error，详情可能显示成“上次抓取失败”。
- 建议：区分“未获取”“文件已丢失”“已获取”；索引、AI 精读、分类各有自己的状态与错误字段，按任务显示重试入口。
- 验收：文件移走后有明确提示并能定位或重新关联；分类失败不影响 PDF 获取记录；文件、索引和精读状态可同时表达。

### 3. P1 — PDF 进度把历史累计数量当成当前批次

- 代码证据：`paperwhale_server/services/pdf_fetch.py:73` 按持久化任务表统计全部成功/失败；`web/js/app.js:111` 用 done/(done+active) 画进度，结束提示也直接用累计计数。
- 影响：以前处理过很多论文后，下一次只获取一篇也可能从很高的进度开始，并报出以前的失败。
- 建议：增加 batch_id，当前批次和历史记录分开。任务面板保留本次成功/失败结果，支持仅重试本批失败项；进度不应在结束后立即消失。
- 验收：已有 100 次历史任务时，新批 3 篇从 0/3 开始，结束仅统计这 3 篇。

### 4. P1 — 非聊天异步操作仍存在旧结果覆盖新选择的路径

- 代码证据：`web/js/library.js:373`、`:412`、`:425` 在精读、查找、标签结果返回时直接 showDetail(result.paper)，没有检查当前 selectedId。
- PDF 缩略图的异步 render 也引用全局 detailPdf.doc，而不是固定本次请求的 doc；`web/js/reader.js:1093` 的全文搜索跨 await 反复读取 state.doc，结束后直接跳页。
- 建议：这些操作复用聊天已经采用的请求令牌/对象归属规则。结果可保存到所属论文，但仅更新仍属于该论文的界面；切换后取消旧搜索和缩略图渲染。
- 验收：A 发起精读/搜索/缩略图加载后切到 B，A 的返回不能把 B 的详情或页码改回 A 的状态。
- 此项为代码审查确认的竞态路径；本轮未逐个构造延迟网络复现。

### 5. P1 — 持久化聊天可以直接永久清空，缺少恢复入口

- 代码：`web/js/chat.js:119`、`web/js/profile-chat.js:130`、`web/js/reader.js:1604` 直接删除；后端清空物理删除历史。
- 建议：优先提供短时撤销或会话回收站，说明清空范围；附件一并移除的影响应可见。论文删除、批量操作与后续备份恢复统一考虑。
- 验收：误点后能恢复该会话，其他会话与已保存画像/分类偏好不变。

## 优先处理：日常显示与阅读

### 6. P2 — 新增 PDF 设置控件样式没有收齐

- 实际截图：`05-settings-pdf.png`。邮箱、浏览器下拉框、用户配置输入明显是浏览器原生样式，尺寸和对齐与邻近控件不一致。
- 根因：`web/css/style.css:119` 漏掉 input[type=email]、不带 type 的 input 和普通 select；`web/index.html:306`、`:313` 对应控件恰好未匹配。
- 建议：统一输入框/下拉组件样式、全宽、行高、边距和焦点；复选框使用统一的 label 布局。
- 验收：所有设置控件在相同网格下对齐，不出现短而窄的原生框，Windows 缩放后仍可读。

### 7. P2 — 紧凑列表固定像素列宽，标题过早截断

- 实际截图：`01-library.png`。1500 宽窗口有明显剩余空间，但长标题、期刊和作者已截断。
- 根因：`web/js/library.js:524` 默认列宽固定为 320/160/140/56/80；applyCompactColumns 将全部列写成 px，覆盖 CSS 的自适应 minmax。
- 建议：标题列吃剩余空间，其余列有限宽；支持两行标题、紧凑/舒适密度、列显示和恢复默认。保留现有拖动列宽功能，增加明显的操作提示。
- 元信息大量使用 11–12px 淡色字，建议把主要元数据提高到 12–13px，状态用简短徽标和文本，避免仅靠边框颜色。
- 验收：宽窗口增加时标题可见长度增加；详情打开后不挤坏核心列；布局在常用桌面缩放下可读。

### 8. P2 — 阅读位置、缩放和侧栏布局没有恢复

- 实测：阅读第 3 页，关闭再打开后回到第 1 页。`web/js/reader.js:1169`、`:1791`、`:1844` 重置页码。
- 小窗口实测：1100 宽时 PDF 区 670px，聊天内容区约 393px。等待 resize 稳定后能正确缩放，但正文已很小；固定侧栏比例不适合持续阅读。
- 建议：按论文保存页码、页内位置、缩放和当前标签；来自引用的目标页优先于保存位置。侧栏可拖宽、折叠，并提供适合宽度/适合页面/原始大小入口。
- 验收：普通重开恢复进度，从引用打开仍跳到引用页；窄窗口可暂时收起侧栏读原文。

### 9. P2 — 全文搜索定位粒度仍是页，没有命中高亮

- 代码：`web/js/reader.js:1093` 只把含关键词的 pageNum 放入数组，结果数显示的是匹配页数。
- 建议：标出具体命中词，显示“第 2 / 18 处”，支持上一处/下一处；搜索过程中显示进度，可取消，切换论文时自动停止旧搜索。
- 标注笔记当前仍使用 window.prompt，建议改为页内小编辑器，支持持续修改与保存状态。

## 下一轮：AI 与全局交互

### 10. P2 — 来源卡片要表达证据类型与实际使用情况

- `web/js/chat.js:60`、`:183` 来源/文件入口一律写“打开全文/查看全文”，但部分条目可能只有摘要或元数据。
- `paperwhale_server/services/rag.py:457` 在模型没有给编号时仍返回前三条检索片段，界面未区分“实际引用”与“检索候选”。
- 建议：明确原文、摘要、AI 概述、附件和网页来源；没有 PDF 的按钮显示“查看摘要/补齐 PDF”。引用编号与对应卡片一一匹配，未被引用的检索结果放在单独折叠区。
- 可补充“选中几篇论文进行比较”和“将回答存入本篇笔记”，让全库与单篇协作更可控。

### 11. P2 — AI 等待过程与模式缺少用户控制

- 当前论文对话默认联网和深度思考，界面只有说明；常用入口缺少本轮关闭选项。长请求主要显示统一等待文案，无法区分检索、读取材料和生成回答。
- 建议：提供“快速/深入”和联网开关，展示本轮材料范围及简短阶段状态；逐步接入流式回答、停止生成和重试。常见的单句翻译不必自动经过最慢路线。
- 左下状态目前主要按 Key 是否配置判断（`web/js/app.js:65`），应区分“已配置未测试”“最近连接成功”“最近失败”。

### 12. P2 — 设置分组与保存反馈可更清楚

- 现状：模型、PDF、画像并排，保存设置在顶部；画像又有独立保存。部分输入立即生效与需保存的边界不够明显。
- 建议：按“模型与连接 / 阅读与 AI / PDF 来源与登录 / 数据与存储 / 插件”分组；每组明确保存与未保存状态。文件路径提供打开目录，迁移操作放在存储组。模型连接错误显示在对应字段旁。
- 搜索无结果的标题/说明已经区分了空库，但主按钮仍是“去导入”（`03-filtered-empty.png`）；应优先给“清空筛选”。

### 13. P2 — 键盘和辅助技术支持需补一轮

- 实测：画像弹窗没有 dialog/aria-modal，Tab 很快移到弹窗外的导航、设置按钮和输入框。合成页面中有 20 个未关联 label/aria-label 的输入或选择控件，此计数包含当前隐藏页面，不等于 20 个可见错误。
- 建议：对话框焦点限制与退出后焦点恢复、Esc 关闭、按钮可见焦点、图标按钮可访问名称、标签页状态、异步提示 aria-live；可点击来源/目录项支持键盘操作。
- 参考：[Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)。

## 交互审查结论

| 维度 | 结果 | 主要依据 |
| --- | --- | --- |
| 可点击性 | 轻微问题 | 部分来源文字、列宽操作和折叠详情的提示不足 |
| 状态可见性 | 明显问题 | 文件状态、分类错误字段、批次进度、已配置与已连通混淆 |
| 主操作清晰度 | 轻微问题 | 顶部双主按钮、不同设置保存范围、空结果主按钮 |
| 操作可发现性 | 轻微问题 | 列宽拖动、缺少后续列表入口和阅读布局控制 |
| 信息负担 | 轻微问题 | 设置并列且保存分组不明，聊天底部长期展示技术预算说明 |
| 内容优先级 | 明显问题 | 标题固定宽度过早截断，剩余宽度未利用 |
| 扫读 | 轻微问题 | 小字号淡色元数据、复合状态长文本 |
| 渐进展示 | 轻微问题 | 已有详情/标签页/诊断折叠可保留，任务结果与高级设置还可分层 |

## 建议实施顺序

第一轮：修复列表分页与全库排序、文件/错误状态、当前批次进度；同时收齐表单样式和列表自适应列宽。这一轮能同时减少误导和明显的显示问题。

第二轮：阅读位置恢复、侧栏拖宽/折叠、全文命中高亮、非聊天异步结果隔离。

第三轮：任务中心、会话撤销/备份、证据卡片、AI 模式与流式输出、设置分组、键盘无障碍。

截图与测量属于审查产物；本轮未实施上述生产行为或样式变更。
