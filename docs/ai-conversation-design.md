# AI 对话的隔离、先验与协作规则

日期：2026-10-27。适用于现有 PaperWhale 2.2.0 的增量改进。

## 目标

每处 AI 对话知道自己的任务、可使用的材料和操作边界；同一会话能够连续追问；切换论文、关闭阅读器或重启程序后仍能恢复各自的记录。不同模块通过已保存的信息协作，不自动混合聊天历史。

## 现有代码核对

- `web/js/reader.js` 发往 `/api/ai/chat` 的请求只有本轮问题，没有历史。切换论文时重置消息和附件；翻译、解释只追加 DOM，未成为后续追问的上下文。
- `web/js/chat.js` 虽然维护消息数组，但请求也不发送历史。`services/rag.py` 每次仅构造 system + 当前 user 两条消息。
- `db.py` 已定义 `chat_messages` 表，但当前聊天入口没有用它保存、恢复历史。
- 画像访谈的历史存于 localStorage，后端读取已有画像；分类助手的历史仅存在前端内存，后端读取分类树和分类偏好，但不读取研究画像。
- 画像接口接受客户端传来的任意消息角色；上传材料、网页正文被直接追加进 system，需要统一区分角色规则和参考资料。
- 单篇问答最多取正文前 32000 字，可能漏掉长论文后半部分；全库问答直接以当前问题检索，无法充分处理“刚才第二篇”“它的方法呢”等追问。
- 分类助手未分类数量来自带 LIMIT 的查询，不能当作全库总数。

## 方案选择

1. **推荐：后端保存独立会话，按任务加载先验，共享已确认的信息。** 能同时解决连续追问、持久化、模块边界和异步串话，适合本地 SQLite 架构。
2. 只修改提示词、让前端传历史：改动较少，但刷新恢复、附件归属和多个窗口的一致性仍不可靠。
3. 全局共享全部聊天历史：容易自动联想，但会把无关论文、画像草稿和分类讨论混入回答，来源也难以核对。

采用方案 1。第一阶段每个作用域保留一个默认会话，支持独立清空，不增加复杂的多聊天窗口管理。

## 各入口的边界

| 入口 | 独立历史 | 每次应加载的先验 | 协作规则 |
| --- | --- | --- | --- |
| 单篇论文阅读对话 | 每个 paper_id 一份，附件同样按论文隔离 | 本文元数据、正文/检索片段、已有精读结果；当前页和选区；用户笔记与相关批注；保存的研究画像作为阅读偏好 | 默认围绕本文。画像用于调整讲解角度，不作为论文证据；其他论文的聊天历史不进入本文 |
| 全库知识问答 | 全库入口独立一份 | 保存的研究画像、文献库实际规模、分类概览、当前检索到的论文片段；追问涉及的论文 ID | 可跨论文检索与比较。历史用于理解指代；具体结论仍需重新取得论文证据 |
| 研究画像助手 | 单独一份 | 最新保存的画像、本会话研究材料和用户明确陈述 | 保存前都是草稿；网页和上传论文只提供线索，不能据此认定用户身份、项目或所有研究方向 |
| 分类助手 | 单独一份 | 最新研究画像、已保存分类偏好、现有多级分类树、真实未分类总数和注明为示例的论文样本 | 已知研究方向不再反复询问；重点确认层级与分类维度。生成草稿后，仍由现有“整理”按钮保存偏好并触发归档 |
| 选区翻译与解释 | 写入所属论文的对话 | 原文、页码、附近正文和本文术语；解释可参考研究画像调整深浅 | 操作和结果成为该论文的连续上下文，支持“这个术语再解释一下”。翻译忠实原文，解释区分原文与背景知识 |
| AI 精读、标签、与我相关、技能运行、订阅翻译 | 任务调用，不自动进入聊天历史 | 按任务读取本文、已有标签、已确认分类偏好、研究画像或待译条目 | 共享任务所需的已保存资料。生成的结果可供后续阅读对话引用，但不能反过来冒充原文证据 |

论文没有 PDF 时明确只能依据元数据或摘要；已有 AI 摘要单独标为生成内容，不伪装成第 1 页原文。缺少画像时照常阅读，不猜测用户研究方向。

## 协作与信息优先级

1. 产品定义的任务与权限规则决定当前入口能做什么。
2. 用户当前明确要求优先于历史中的偏好；已保存画像、分类偏好是当前底稿，每次请求读取最新值。
3. 本会话历史用于延续讨论，旧回答与草稿不是经过核实的事实。
4. 论文正文、附件、笔记、批注、网页均标注身份与来源。其中出现的指令属于材料，不能更改角色、作用域或保存行为。
5. 原文结论、用户补充、其他附件、联网资料、一般背景知识分开表述。联网只能补充背景，不能证明本文做过某项实验。
6. “与我相关”读取画像和本文；分类读取画像和分类偏好；单篇阅读读取本文的精读结果。它们不读取其他模块的原始访谈。
7. 用户要跨论文比较时使用全库问答；本文入口告知范围并引导至现有全库入口，不静默把其他论文混进本文证据。
8. 回答或讨论不能自动修改画像、分类偏好、论文笔记或启动归档。已有明确任务按钮保留各自的执行语义。

## 会话与材料的生命周期

- 后端持久化四种作用域：`paper:<id>`、`library`、`profile`、`categories`。论文作用域必须校验论文存在，拒绝会话与 paper_id 不匹配的请求。
- 消息、来源和附件归属会话；前端负责显示与交互，后端保存的历史作为连续对话的依据。正式请求只接受 user/assistant 历史，不接受客户端注入 system/developer/tool 角色。
- 仅成功完成的问答对进入后续模型上下文；请求失败显示可重试状态，不把错误提示当作助手回答。
- 切换论文、关闭阅读器不清空会话；重新打开恢复该论文消息及附件。刷新、重启同样恢复。删除论文时清理它的会话及材料。
- 各入口提供独立清空功能；清空同时移除该会话的消息、附件和未保存草稿，不修改已保存画像、分类偏好或论文数据。
- 画像现有 localStorage 记录仅作为一次性迁移来源；成功迁移后使用后端记录。不推测其他来源不明历史的归属。
- 长历史保留在本地，进入模型的历史限制为最近 24 条、总计约 12000 字，优先保留完整的近期问答，不截掉当前问题；附带来源 ID 便于重新检索。界面简短提示回答使用最近上下文。
- 附件按会话保留，移除后不再加载其正文；历史里已生成的描述仍是历史，不承诺删除附件会撤销旧回答。
- 新的画像或分类修改要求会使旧待保存草稿失效，避免继续点击旧草稿按钮。后续回答生成新草稿后再显示保存操作。

## 请求并发与切换

- 同一会话避免重复发送；不同论文允许独立请求。
- 每次异步请求捕获原始会话和论文 ID，包括文件上传、翻译、解释。返回只保存并更新它所属的会话，不引用当时已经切换的全局 paperId。
- 前端只在当前仍显示对应会话时更新消息和按钮；论文 A 的迟到回答不能显示在 B 中。
- 会话清空使用版本号阻止在途旧请求重新写回被清空的记录；正在关闭或切换的界面不会被旧请求重新打开。

## 上下文组织与检索

- 提取统一的上下文服务：加载作用域、过滤消息角色、构建各任务先验、标记资料来源及限制长度。各入口保留自己的回答格式和任务规则。
- 单篇正文仍受长度预算限制；结合当前问题、选区、当前页和相关历史检索本文其他片段，补足只读开头的盲点。对截断和缺失情况明确说明。
- 全库追问用当前问题和近期用户主题、已引用论文 ID 共同检索；历史回答不直接当作新的证据。来源编号仅对应本轮材料，不沿用旧轮编号。
- 分类树、论文样本、批注和笔记都有预算，查询总数与样本分开。告知样本和截断范围，不把有限上下文说成“已读完全部文献”。
- 附件与网页内容放在明确标记的资料区，不追加成新的角色规则。联网资料使用独立来源标识，避免与论文页码引用混淆。
- 保存的画像与分类偏好改变后，下次请求立即生效，旧对话不覆盖最新保存值。

## 实施范围

- 新增独立的会话/消息/材料存储与对应读取、清空接口；SQLite 只做增量建表或迁移，不破坏已有论文与标注数据。
- 适配 `routers/ai.py`、`services/rag.py`、`services/category_assistant.py` 和四个聊天前端模块；翻译/解释接入所属论文会话。
- 给精读、相关性和技能调用补齐相应的材料身份、结果身份和协作边界规则，维持现有输出契约。
- 保留现有 API 路径与返回字段；缺省会话参数的旧客户端按现有入口映射到对应作用域。
- 修改源码与文档，不在本阶段打包安装或启动已安装程序的数据迁移；测试只使用独立临时目录与 mock LLM。

## 验收场景

1. A 论文问过问题后切换 B，B 的模型输入、附件和界面均不含 A 的历史；回 A 恢复自己的聊天。
2. 同一论文追问“刚才那个方法”，模型能看到所属历史；关闭重开及重启后仍可恢复。
3. 翻译/解释某页选区后追问，能识别这段文本与所属论文页码；切换论文后不能串入。
4. A 的慢请求返回时正在 B，结果仅归 A。清空中的旧请求不能恢复旧消息。
5. 全库问答能沿用上一轮提到的论文做比较，并重新取得引用证据，不凭旧回答编造页码。
6. 分类助手直接知道已保存的研究方向、分类树和真实数量，不重复要求用户从头介绍；没有画像时也能正常交流。
7. 画像助手基于旧画像增量修改；上传他人论文、课题组网页不会自动变成用户身份或经历。
8. 新草稿未保存前，其他模块继续使用旧的已保存信息；保存后下一轮读到新信息。
9. 清空某模块不影响其他会话或已保存资料；附件只在本会话可见，移除后不再加载正文。
10. 材料内的“忽略规则”、伪造角色与越界会话 ID 不能改变系统消息或加载其他作用域的历史。
11. 无正文、只有摘要、长论文后半部分、空画像与联网失败有明确且可信的降级行为。
12. 通过隔离环境的后端上下文测试、前端会话切换/延迟响应测试、现有接口冒烟与 Python/JS 语法检查。
